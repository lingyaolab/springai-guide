请求阶段

你会看到 因为 改成
401 Unauthorized key 无效、欠费，或 base-url 指向了另一个网关 先用 curl 直连厂商验证 key，再回来查代码
404 Not Found base-url 多了或少了一段路径 用默认 https://api.deepseek.com，别手拼 /chat/completions

输出与解析

你会看到 因为 改成
模板报 Not all variables were replaced... 提示词里写了 JSON 花括号，被当成占位符 转义花括号，或换 < > 分隔符
entity() 解析失败 / 返回 null 模型输出带解释文字、markdown，或字段名不匹配 加 validateSchema()；用 @JsonProperty 对齐字段
content() 返回 null，后续 NPE 没有文本内容（例如只有工具调用） 先判空，或改用 chatResponse() 看结构
流式接口一次性返回 MVC 栈返回 Flux，或代理缓冲 MVC 用 SseEmitter，WebFlux 返回 Flux，关掉 proxy_buffering
流式接口 30 秒断开 SseEmitter 没设超时，继承了容器默认的异步超时（Tomcat 常见 30 秒） 构造时传 0L 或设置足够大的超时
流式接口接了 Flux 但无输出 冷流没有被订阅 交给框架订阅，或显式桥接到 SseEmitter

检索与工具行为异常（不报错）

现象 因为 改成
模型总说「资料中没有」 阈值太高或切块太碎，检索为空 先把阈值降到 0 验证能召回，再逐步上调
回答无关内容 默认阈值 0.0，前 K 条全塞进上下文 提高阈值、加 metadata 过滤、降低 topK
带工具的对话里 RAG 检索多次 RAG Advisor order 为 0，位于工具循环内侧 把 order 调到小于 MIN+300，或接受每轮重检
工具报错但接口 200 默认把异常转成消息回给模型 关键工具设 spring.ai.tools.throw-exception-on-error=true
降级到备用模型后结构化输出失败 备用模型不支持原生 structured output 降级时改为纯文本，或只对非关键路径降级
429 直接失败、不重试 429 属于 4xx，默认归类为不可重试 spring.ai.retry.on-http-codes=[429]

MCP 专项

现象 因为 改成
连上了但工具列表为空 类不是 Spring Bean、方法不是 public、或引错 starter 加 @Service；HTTP 场景用 -webmvc / -webflux
Windows 上 stdio 起不来 npx 是 .cmd 脚本 command: cmd + args: ["/c", "npx", ...]

/mcp 返回 401 / 跳登录页 Spring Security 默认拦截 为 /mcp/** 配置认证方式并处理 CSRF

排查顺序

  • ① 先分层
    是启动失败、请求失败、还是输出不对？三类的原因完全不同。
  • ② 看第一个异常
    Spring 的异常链很长，最内层的 Caused by 才是真正原因。
  • ③ 确认配置生效
    用 /actuator/env 或启动日志确认属性的最终值，别只看 yml。
  • ④ 缩小到最小复现
    去掉 Advisor、工具、RAG，只留一次 call()，看它还崩不崩。
  • ⑤ 打开观测
    看 trace 里哪一层耗时或报错，比读代码猜快得多。

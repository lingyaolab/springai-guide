附录 D · 版本迁移

从 Spring AI 1.1.x 升到 2.0，大部分代码能编译，但配置项、记忆 Advisor、工具注册方式 有硬性变化。这一页按「先升什么、再改什么」排序，每条都标了官方 upgrade-notes 的位置。

这次升级到底动了什么

层 变化 影响
运行时 要求 Spring Boot 4.0.x / 4.1.x Boot 3.x 工程不能直接升
配置 所有模型的 .options 层级被拍平 属性名要改，旧写法已弃用
记忆 会话 ID 必填、默认 order 改为 MIN+200、移除两个 API 运行期抛异常或编译失败
工具 ToolCallingAdvisor 自动注册、ToolSpec API 移除 重复注册会执行两次
客户端 .options() 只收 Builder 编译期报错

推荐升级顺序

  • ① 先升 Boot，再升 Spring AI
    先把工程升到 Boot 4.1.x 并跑通现有测试，再引入 2.0 BOM。两个大版本一起升，出问题很难定位。
  • ② 换 BOM 与 starter 坐标
    统一成 spring-ai-starter-model-* / spring-ai-starter-vector-store-*。
  • ③ 批量改配置
    去掉 .options，显式设置 temperature（默认值已移除）。
  • ④ 改记忆与工具代码
    会话 ID 改为每次调用传；删除手动注册的 ToolCallingAdvisor。
  • ⑤ 迁移数据库
    JDBC 记忆表补 sequence_id；向量库按新维度重建。
  • ⑥ 跑回归集
    温度默认值、记忆 order、工具循环都变了，输出风格与调用次数可能不同。

    • 配置：去掉 .options，补上温度

    2.0 把所有模型（chat / embedding / image / audio / moderation / OCR）的嵌套 options 层级拍平：原来的 xxx.options.model 变成 xxx.model。旧属性还留着兼容，但嵌套的 Options 类与 getOptions() 都已弃用。 

    # 之前
spring.ai.deepseek.chat.options.model=deepseek-chat
spring.ai.deepseek.chat.options.temperature=0.7

# 之后
spring.ai.deepseek.chat.model=deepseek-v4-flash
spring.ai.deepseek.chat.temperature=0.7

    拍平说明upgrade-notes.adoc:830。

    默认温度被移除了

    1.x 里 Spring AI 给大多数模型设了 0.7 的默认温度；2.0 改为使用厂商自己的默认值。 升级后如果你依赖过 0.7，输出风格会变，必须显式配置。 upgrade-notes.adoc:2223

    starter 也要换成新命名。2.0.2 的 starters/ 目录里是 spring-ai-starter-model-openai 这种形式；1.x 的 spring-ai-openai-spring-boot-starter 已经不存在。

    当前命名starter-model-openai/pom.xml:10。

    记忆：四个硬变化

    变化 你会遇到 怎么改
    会话 ID 必填 运行期 IllegalArgumentException: conversationId cannot be null 每次调用传 ChatMemory.CONVERSATION_ID
    移除 DEFAULT_CONVERSATION_ID 编译失败 用自己的会话 ID 生成规则
    移除 Builder 的 .conversationId() 编译失败 改为调用时传参
    移除 PromptChatMemoryAdvisor 编译失败 换成 MessageChatMemoryAdvisor，Builder 用法一致
    默认 order 从 MIN+1000 改为 MIN+200 记忆位置变化，工具消息不再进记忆 默认就是「环外」，需要环内时显式调 order 并关闭内部历史
    JDBC 表新增 sequence_id 旧表无法正确排序 加列并按会话顺序回填

    会话 ID 必填upgrade-notes.adoc:1363； 移除常量upgrade-notes.adoc:1369； 移除 Builder 方法upgrade-notes.adoc:1390； 移除 Prompt 版 Advisorupgrade-notes.adoc:1450； order 变化upgrade-notes.adoc:407； sequence_idupgrade-notes.adoc:741。

    工具：别再加第二个 ToolCallingAdvisor

    2.0 的 DefaultChatClient 会自动注册一个 ToolCallingAdvisor。 你原来手动加的 .advisors(ToolCallingAdvisor.builder().build()) 会导致链上出现两个， 工具被执行两次。 

    // 之前：手动注册
chatClient.prompt("今天天气")
    .tools(weatherTool)
    .advisors(ToolCallingAdvisor.builder().build())
    .call().content();

// 之后：交给自动注册
chatClient.prompt("今天天气")
    .tools(weatherTool)
    .call().content();

    另外，tools(Consumer<ToolSpec>) 与 ToolSpec 接口被移除； .tools(...) 现在直接接受 ToolCallback、ToolCallbackProvider、 @Tool 对象及其数组/集合。工具上下文改用独立的 .toolContext(...)。

    自动注册与 ToolAdvisor 标记upgrade-notes.adoc:1090； ToolSpec 移除upgrade-notes.adoc:1154。

    ChatClient：options 只收 Builder

    // 之前：传构建好的实例
Options opts = DeepSeekChatOptions.builder().temperature(0.2).build();
chatClient.prompt().options(opts).call().content();

// 之后：传 Builder
chatClient.prompt()
    .options(DeepSeekChatOptions.builder().temperature(0.2))
    .call().content();

    这个约束只作用于 ChatClient；直接调 ChatModel.call(Prompt) 时，Prompt 里仍要放 完整构建的 Options，而且模型不会做字段级合并。

    Options Builder 约束upgrade-notes.adoc:1476。

    模块与依赖：几个改名与移除

    旧 新 说明
    spring-ai-advisors-vector-store spring-ai-vector-store-advisor RAG Advisor 所在模块
    spring-ai-autoconfigure-model-chat-memory-redis ...-chat-memory-repository-redis 2.0.1 改名，配置前缀同步变化
    spring.ai.chat.memory.redis.* spring.ai.chat.memory.repository.redis.* 旧前缀已弃用
    spring-ai-hanadb-store 已移除 需要换向量库

    Advisor 模块改名upgrade-notes.adoc:376； Redis 改名upgrade-notes.adoc:48； 移除模块upgrade-notes.adoc:1357。

    迁移检查清单

    检查项 确认方式
    Boot 版本 mvn dependency:tree 里是 4.0.x / 4.1.x
    starter 坐标 没有 *-spring-boot-starter 形式的旧 AI 依赖
    配置项 全局搜索 .options.，确认已去掉
    温度 需要固定行为的地方显式设置
    记忆 所有记忆调用都传了 CONVERSATION_ID
    工具 没有手动注册 ToolCallingAdvisor
    数据库 JDBC 记忆表有 sequence_id
    向量库 维度、模型、索引三者一致

    迁移期最常见的四个坑

    能编译，但启动报 NoSuchMethodError

    Boot 还是 3.x，或者某个传递依赖把旧版 Spring 拉了进来。用 dependency:tree 找出来排掉。

    记忆突然「不记得」了

    默认 order 变了，记忆现在在工具循环外；或者没传会话 ID，异常被上层吞掉。先看日志里的第一个异常。

    工具执行两次

    链上有两个 ToolCallingAdvisor。删掉手动注册的那个。

    回答风格变了

    默认温度从 0.7 变为厂商默认值。想保持原样就显式配置。

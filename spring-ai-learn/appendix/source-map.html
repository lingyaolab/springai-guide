附录 E · 源码地图

官方文档讲「怎么用」，源码讲「到底怎么实现的」。这一页给仓库的模块划分与入口文件， 让你遇到「文档没说清」时知道该打开哪个文件。

怎么读源码

  1. 先看接口，再看实现：ChatModel → DeepSeekChatModel。
  2. 配置类优先：*Properties 决定你能配什么，默认值都在字段上。
  3. 自动装配决定「什么时候生效」：@ConditionalOn* 比实现更能解释「为什么没有 Bean」。
  4. 测试是最好的用法示例：src/test 里通常有最小可运行配置。

厂商实现：换模型看这里

每个厂商一个模块，结构几乎一样：XxxChatModel（协议转换）、XxxChatOptions（参数）、 XxxApi（HTTP 客户端）。以 DeepSeek 为例：

文件 看什么
DeepSeekChatModel.java:200 如何把 Prompt 转成请求、处理工具循环
DeepSeekChatOptions.java:44 实现了哪个 Options 接口（决定支持哪些能力）
DeepSeekApi.java:156 同步/流式 HTTP、SSE 解析、chunk 合并
DeepSeekApi.java:61 默认模型、模型枚举与弃用标记
判断「这个能力厂商支不支持」的最快方法

看它的 Options 实现了哪些接口：ToolCallingChatOptions 决定能不能调工具， StructuredOutputChatOptions 决定能不能用原生结构化输出。

文档源：比官网更早一步

spring-ai-docs/src/main/antora/modules/ROOT/pages/ 就是官方站点的源文件。两个最值得读的：

  • api/chatclient.adoc：ChatClient 的官方语义与示例。
  • upgrade-notes.adoc：所有破坏性变更的权威清单，按版本倒序排列（2.0.2 在最上面）。 遇到「升级后行为变了」，先来这里搜关键词。
文档与源码冲突时信谁

信源码，但要确认你读的是 v2.0.2 tag 的源码。本站的每一条结论都对应到具体文件行， 你可以在 GitHub 上按 tag 复核。

00 · 学习地图

这一章不写代码，只解决三个问题：官方文档已经很全，为什么还要看这里、这个站该怎么读、 你现在缺的是哪块前置知识。读完再决定从第几章开始。

为什么要再造一个文档站

官方中文站（docs.springframework.org.cn）质量很好，而且已经是中文。但它是一份 reference：按能力分篇，假设你知道自己要找什么。 初学者打开它，最常见的状态是「每一页都看得懂，但不知道先看哪一页」。

官方文档的立场 初学者遇到的后果 本站怎么处理
按能力组织：chat / tools / RAG / vectors 各一篇 看完 chat 篇还不知道下一步该干什么，也不知道它们怎么组合成一个服务 按落地顺序重排：先能跑 → 再懂调用链 → 最后碰扩展点
默认你已经在 Spring 生态里 不知道为什么配置项前缀长这样，也不知道 @Bean 是谁注册的 把「自动装配」当主线讲：每个配置项都能指回一个 Properties 类
示例是片段，不承诺可编译 复制下来缺 import、缺依赖、缺 key，报错信息也对不上 每章给完整工程结构，代码块标注文件路径
版本更新快，博客滞后 搜到的例子是 1.x 写法，2.0 已经改名或删掉了 每章标 2.0.2 的破坏性变更，附录 D 集中列迁移表
本站不做什么

不重复 API 参考、不逐条翻译配置属性、不解释 MCP 协议规范本身。这些官方文档做得比一本教程更好，而且更新更及时。 本站只补四件事：顺序、可运行、选型、踩坑。

三条学习主线：同一章读三遍

每一章都切成三种可读法。不必一次全读，但别只读第一种——只照抄不改，一周后还是不会。

① 跟做线

  • 「读完你能做到」+「最小可跑」+「逐行解读」
  • 目标：10 分钟内看到程序真的输出东西

② 理解线

  • 「端到端」+「速查表」
  • 目标：知道配置在哪个环节变成 Bean，数据在哪个环节变成字符串

③ 避坑线

  • 「陷阱与窍门」+「自检三问」+「动手练习」
  • 目标：出错时能自己定位到具体配置项或代码行

实际建议：第一遍只走 ①，把代码跑起来；第二天通勤路上读 ②；等你真的撞到错误，再回来读 ③。 这时候的阅读吸收率最高，因为你带着问题来。

为什么把「环境与依赖」单独一整章

Spring AI 最容易失败的地方不是 API 用错，而是依赖和版本没对齐：Spring AI 2.0 需要 Spring Boot 4.xgetting-started.adoc:8，而网上大量教程还是 Boot 3 + 1.x 的坐标。这一章把「装错」的每一种表现都列出来，比后面任何一章都省时间。

前置知识自查：这些不会会卡在哪

不需要精通，但下面每一条都会在具体章节里用到。括号里是「不会时会卡住的第一处」。

  • Spring Boot 基础：@ConfigurationProperties、@Bean、自动装配、 application.yml 的层级写法（卡在 01 章：不知道为什么只写 key 不写前缀也能生效）
  • Maven 依赖管理：dependencyManagement、BOM、mvn dependency:tree （卡在 01 章：不知道该不该写 <version>）
  • Java 17 语法：record、文本块、var（卡在 02 章：示例里的 record Answer(...) 看不懂）
  • HTTP 与 JSON：请求头、状态码、流式响应（卡在 02 章：不知道 401 和 404 分别是谁返回的）
  • Reactor 一点点：Flux、subscribe、为什么流式要返回 Flux（卡在 04 章；02 章只需要会读，不需要会写）
如果你完全没写过 Spring Boot

先去把官方 guide 的 Building a RESTful Web Service 跑一遍，大约 30 分钟。本站不会重复讲 @RestController、依赖注入这些内容。

没有 API Key，能学到哪一步

DeepSeek 需要一个有效的 key（多数情况下要充值），但本站大部分内容是「读 + 编译」，不调用模型也能完成。按章节看：

阶段 没有 Key 能做什么 需要 Key 才能看到的现象
00–01 章 建工程、写配置、mvn compile、看懂自动装配链路 启动后第一次真实请求（401 也说明连通了，但要看到回答必须有 Key）
02 章 读懂 ChatClient 的每个方法、把参数改成自己的 流式输出的首字延迟、多轮记忆是否真的记住
03 章之后 结构化输出、RAG、工具的代码结构与配置 模型是否真的按 schema 返回、召回质量、工具是否被正确调用
想完全零成本跑通

可以换成本地 Ollama（spring-ai-starter-model-ollama）。本站默认用 DeepSeek，是因为它便宜、 国内直连、并且兼容 OpenAI 协议；换成 Ollama 只需要改依赖和三个配置项，01 章会给出对照。

事实来源：我怎么保证不编

本站只认 Spring AI 2.0.2 这一份源码。每个「默认值是 20」「前缀是 spring.ai.deepseek.chat」「这里会抛 IllegalArgumentException」都带 file:line， 并在发布前用脚本核对：

  • node tools/check-sources.cjs：每条出处的文件是否存在、行号是否越界、大小写是否与磁盘一致
  • node tools/check-site.cjs：站内链接、锚点、导航与实际小节标题是否一致

如果官方文档与源码冲突，以源码为准，并在正文里同时给出两边出处——这类差异会集中在附录 D。

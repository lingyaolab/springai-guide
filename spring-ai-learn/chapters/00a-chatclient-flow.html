最小链路：一次 call() 的 9 个节点

        

          L1 只有 9 个节点：用户输入组装成 Prompt，Advisor 链排序后调用 ChatModel；
          模型要工具就执行工具再推理，最后统一从 ResponseSpec 取结果。这条链路里没有记忆、RAG、观测与 SSE。
        

        

          

            
              
节点它做什么输出给谁

            
            
              
UserInput把问题与模板变量交给 ChatClient.prompt()Prompt

              
Prompt拼 system / user 消息与运行时 ChatOptionsAdvisorChain

              
AdvisorChain按 order 排序，越小越靠外ChatModel

              
ChatModel第一次推理，可能产出 tool_callsToolCallingAdvisor

              
ToolCallingAdvisor检测工具调用；没有工具就直接返回ToolCallback

              
ToolCallback执行 Java 方法，产出 ToolResponseMessage下一轮上下文

              
ChatModel 2带着工具结果再次推理ResponseSpec

              
ResponseSpec统一收口：content() / entity() / chatResponse()调用方

              
Output返回字符串、实体、ChatResponse 或 SSE 帧Controller / 前端

            
          

        


        
工程化：加的 5 个节点

        

          L2 不是另起一条链路：它在 L1 的 9 个节点上新增 5 个，共 14 个。
          新增的是 ChatMemory、RAG、StructuredOutput、Observation、Streaming。
        

        

          

            
              
L2 的层插在哪它改变什么

            
            
              
ChatMemory +L2Advisor 链入口按 conversationId 注入历史，再把新一轮写回

              
RAG +L2ChatModel 之前检索上下文替换最后一条 user 消息

              
StructuredOutput +L2ResponseSpec 之前JSON 转实体；校验失败可重试

              
Observation +L2整条链旁路ChatClient / ChatModel / Tool 的 trace 与 metric

              
Streaming +L2ResponseSpec 之后Flux 增量输出，可接 SSE

            
          

        


        
生产化：再加 8 个外围节点

        

          L3 在 L2 的 14 个节点上再加 8 个，共 22 个：
          Auth、Gateway、Retry、ModelRouter、MCP Client、MCP Server、Evaluation、Deploy。
          注意它们不是都塞进模型循环：Auth / Gateway 在入口，MCP Client / Server 在工具面，
          Evaluation 在发布前，Deploy 在运行环境。
        

        

          

            
              
外围设施接在哪对信息流的影响

            
            
              
Auth入站之前把请求变成可信的用户与租户上下文

              
Gateway / 限流入站之后路由、配额与并发保护

              
Retry模型调用外对限流与网络错误退避重试

              
ModelRouterChatModel 之前按任务、成本与可用性选模型

              
MCP Client工具面把远端 MCP 工具变成 ToolCallback

              
MCP Server能力出口把自己的 @McpTool 暴露给其他 Agent

              
Evaluation发布门禁回归集与 judge 模型给出通过率

              
Deploy运行环境容器、密钥、监控与回滚

01 · 环境与依赖

这一章只解决两件事：编译不过和能写出第一行真的能跑的代码。看完你会明白 spring-ai-bom / spring-ai-starter-model-deepseek / spring-ai-autoconfigure-model-deepseek / spring-ai-deepseek 这四层各管什么， 以及 401、404、No qualifying bean 分别出在哪一层。

读完你能做到

  • 用 Spring Boot 4.1 + JDK 17 建一个工程，只引一个 AI 依赖就能启动并拿到模型回答
  • 说清 BOM、starter、autoconfigure、model 四层的分工，以及为什么 spring-ai-starter-model-deepseek 已经顺带给了你 ChatClient.Builder 和 ChatMemory
  • 看到 DeepSeek API key must be set、401、404、No qualifying bean of type ChatModel 时，能直接判断该改配置、改地址还是改依赖

先说为什么：Spring AI 不是一个 jar，是一层装配

第一次接触的人最容易把 Spring AI 当成「一个 SDK」。实际上它按职责拆成了四层，你在 pom.xml 里写的那一行只是入口，真正干活的类在下面三层。

spring-ai-bom（只管版本）
一个只有 dependencyManagement 的 POM，声明这一版 Spring AI 全家桶用哪些版本。 它不引入任何代码，只让你在写依赖时省掉 <version>。 getting-started.adoc:146
spring-ai-starter-model-deepseek（入口 + 传递依赖）
把下面三层和 HTTP 客户端一起打包给你：spring-boot-starter-webclient、 spring-boot-starter-restclient、DeepSeek 自动装配、DeepSeek 实现、ChatClient、ChatMemory。 starter/pom.xml:20 starter/pom.xml:30 starter/pom.xml:42 starter/pom.xml:54
spring-ai-autoconfigure-model-deepseek（把配置变成 Bean）
读 spring.ai.deepseek.* 配置，创建 DeepSeekChatModel。它决定「什么条件下 才创建这个 Bean」——这是排查 No qualifying bean 的第一现场。 DeepSeekChatAutoConfiguration.java:51
spring-ai-deepseek（真正的实现）
DeepSeekChatModel、DeepSeekChatOptions、DeepSeekApi。 负责拼请求体、发 HTTP、把响应转成 ChatResponse。你不直接 new 它。
为什么厂商要单独一个 starter，而不是全塞进一个 jar

不用 DeepSeek 的项目，classpath 里就不该出现它的 SDK、HTTP 客户端和传递依赖。这也是为什么 1.x 时代的 spring-ai-openai-spring-boot-starter 在 2.0 已经统一改名为 spring-ai-starter-model-openai 这类 starter-model-* 形式—— 你在网上抄到的旧坐标，在 2.0 里通常直接解析不到。

最小可跑：一个 Boot 工程 + 三行配置

第 1 步：pom.xml

新建一个 Maven 工程，pom.xml 只留这些内容：

<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
  <modelVersion>4.0.0</modelVersion>

  <parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>4.1.2</version>
    <relativePath/>
  </parent>

  <groupId>com.example</groupId>
  <artifactId>spring-ai-demo</artifactId>
  <version>0.0.1-SNAPSHOT</version>

  <properties>
    <java.version>17</java.version>
  </properties>

  <dependencies>
    <!-- Spring Boot 基础：日志、自动装配、SpringApplication -->
    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter</artifactId>
    </dependency>

    <!-- 唯一的 AI 依赖：DeepSeek 模型 + ChatClient + ChatMemory 一起进来 -->
    <dependency>
      <groupId>org.springframework.ai</groupId>
      <artifactId>spring-ai-starter-model-deepseek</artifactId>
    </dependency>
  </dependencies>

  <dependencyManagement>
    <dependencies>
      <!-- 只在这个工程里生效；Spring Boot parent 不会替你管 Spring AI 的版本 -->
      <dependency>
        <groupId>org.springframework.ai</groupId>
        <artifactId>spring-ai-bom</artifactId>
        <version>2.0.2</version>
        <type>pom</type>
        <scope>import</scope>
      </dependency>
    </dependencies>
  </dependencyManagement>
</project>

本版本的 Java 基线是 17pom.xml:241，构建时对齐的 Spring Boot 是 4.1.2pom.xml:254；Spring AI 2.0.x 官方支持 Boot 4.0.x 与 4.1.xgetting-started.adoc:8。

不要把你项目里的 Boot 3.x 直接升上来「试试」

Spring AI 2.0 依赖 Spring Framework 7 / Boot 4 的新 API。把 2.0.2 的 BOM 塞进一个 Boot 3.5 的工程， 典型结果是编译期找不到方法、启动期 NoSuchMethodError。要么整体升到 Boot 4，要么留在 Spring AI 1.0.x。

第 2 步：application.yml

spring:
  ai:
    deepseek:
      api-key: ${DEEPSEEK_API_KEY}
      chat:
        model: deepseek-v4-flash
        temperature: 0.7

前缀来自 DeepSeekConnectionProperties.java:29 与 DeepSeekChatProperties.java:40； 默认地址是 https://api.deepseek.comDeepSeekConnectionProperties.java:31。

第 3 步：一个能打印回答的类

package com.example.demo;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.boot.CommandLineRunner;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class DemoApplication implements CommandLineRunner {

    private final ChatClient chatClient;

    // ChatClient.Builder 由自动装配提供，作用域是 prototype，注入即得到一个副本
    DemoApplication(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }

    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }

    @Override
    public void run(String... args) {
        String answer = this.chatClient.prompt()
                .user("用三句话解释什么是 RAG")
                .call()
                .content();
        System.out.println(answer);
    }
}

第 4 步：给 key，然后运行

$env:DEEPSEEK_API_KEY = "sk-你的key"
./mvnw spring-boot:run

第一次运行会下载依赖，之后通常 5–15 秒启动。输出大致是：

逐行解读：容易懵的地方

这行 为什么这么写 写错会怎样
spring-ai-starter-model-deepseek 不写版本 版本由 spring-ai-bom 统一管理 全部依赖都写死版本时，spring-ai-deepseek 与自动装配版本可能对不上，报 NoSuchMethodError
spring.ai.deepseek.api-key 属性名来自 setApiKey() 的宽松绑定 写成 spring.ai.deepseek.chat.api-key 不生效——chat 前缀下没有这个属性
chat.model: deepseek-v4-flash 2.0.2 的默认模型就是它DeepSeekApi.java:61 写 deepseek-chat / deepseek-reasoner 仍能请求，但这两个名字自 2.0.0 起已弃用DeepSeekApi.java:253
ChatClient.Builder 注入的是接口 自动装配创建的是 DefaultChatClientBuilder，作用域 prototypeChatClientAutoConfiguration.java:113 自己 new DefaultChatClient(...) 会跳过 Advisor 装配，后面的记忆、工具全部失效
${DEEPSEEK_API_KEY} 用环境变量占位，避免把 key 提交进 Git 写成字面量并在 CI 日志里打印配置，key 会泄露

端到端：从 application.yml 到 ChatModel 实例

启动时依次发生这些事，任何一步失败都会导致「没有 ChatModel」或「有 ChatModel 但请求 401」：

  • ① 绑定配置
    DeepSeekConnectionProperties 拿到 api-key 与 base-url， DeepSeekChatProperties 拿到 model / temperature，后者用 toOptions() 变成 DeepSeekChatOptions。 DeepSeekChatProperties.java:199
  • ② 条件判断：要不要创建 DeepSeek Bean
    只有 spring.ai.model.chat 未设置（matchIfMissing = true）或等于 deepseek 时才装配。DeepSeekChatAutoConfiguration.java:54 常量值是 "deepseek"SpringAIModels.java:55。
  • ③ 建 API 客户端
    解析 base-url 与 api-key，缺任何一个都会在启动时断言失败；然后创建一个 RestClient（同步）和一个 WebClient（流式）。 DeepSeekChatAutoConfiguration.java:88
  • ④ 建 ChatModel
    用 DeepSeekChatModel.builder() 把 API、options、ToolCallingManager、RetryTemplate、 ObservationRegistry 装进去。DeepSeekChatAutoConfiguration.java:71
  • ⑤ 建 ChatClient.Builder 与 ChatMemory
    ChatClientAutoConfiguration 用 ChatModel 建 ChatClient.Builder； starter 顺带引入的 chat-memory 自动装配再给一个内存版 ChatMemory。 ChatMemoryAutoConfiguration.java:44
    • 一句话记住这四层

    BOM 管版本，starter 管依赖，autoconfigure 管条件，model 管协议。 出问题时先问：是版本不对（BOM）、依赖没进来（starter）、条件不满足（autoconfigure），还是请求被厂商拒绝（model）。

    版本对齐：2.0.2 到底要什么

    组件 本站使用 说明
    Spring AI 2.0.2 所有 org.springframework.ai 依赖由 BOM 对齐
    Spring Boot 4.1.2 官方支持 4.0.x 与 4.1.x；Spring AI 自身的构建基线是 4.1.2
    JDK 17 Spring AI 的编译目标；Boot 4 的最低要求
    模型 DeepSeek 默认 deepseek-v4-flash；更强的 deepseek-v4-pro 按需切换

    想换 Ollama 本地跑：把依赖换成 spring-ai-starter-model-ollama，配置换成 spring.ai.ollama.base-url 与 spring.ai.ollama.chat.model，代码一行不用改—— 因为 ChatClient 只认 ChatModel 接口。这也是本站从第 02 章开始只讲 ChatClient、不绑厂商的原因。

    依赖与配置速查

    你要做的事 加什么
    只要对话 spring-ai-starter-model-deepseek
    暴露 HTTP 接口 再加 spring-boot-starter-web（或 -webflux 做纯流式）
    换向量库做 RAG 再加 spring-ai-starter-vector-store-*（第 08 章）
    跑测试 spring-boot-starter-test；模型用自写的 StubChatModel（第 13 章）
    配置项 默认值 作用
    spring.ai.deepseek.api-key 无，必填 DeepSeek 凭证；缺失时启动断言失败
    spring.ai.deepseek.base-url https://api.deepseek.com 换代理或兼容网关时改这里
    spring.ai.deepseek.chat.model deepseek-v4-flash deepseek-v4-flash / deepseek-v4-pro；旧名已弃用
    spring.ai.deepseek.chat.temperature 不设置，交给厂商 0–2；越低越稳定
    spring.ai.model.chat 不设置（等于匹配所有） classpath 上有多个厂商时，用它指定用哪个
    spring.ai.chat.client.enabled true 设为 false 就不会有 ChatClient.Builder

    陷阱与窍门

    你会看到 IllegalArgumentException: DeepSeek API key must be set

    因为启动时没解析到 key，自动装配在创建 API 客户端前直接断言失败。 改成检查三处：spring.ai.deepseek.api-key 是否写对、环境变量是否在当前终端 生效（IDE 里要单独配）、${DEEPSEEK_API_KEY} 是否被引号或空格污染。 DeepSeekChatAutoConfiguration.java:94

    你会看到配置没生效：抄了 spring.ai.deepseek.chat.options.model

    因为2.0.0 起所有模型的 .options 层级被拍平了：原来的 xxx.options.model 现在是 xxx.model。旧写法还留着兼容，但 getOptions() 与嵌套 Options 类都已标记弃用，2.x 后续版本会删。 改成去掉 .options 这一段。 upgrade-notes.adoc:830

    你抄的 deepseek-chat 还能用，但已经不是推荐值

    因为2.0.2 把默认模型换成了 deepseek-v4-flash，并把 deepseek-chat（指向 V3）与 deepseek-reasoner 标记为 @Deprecated(since = "2.0.0")。建议新项目直接用 deepseek-v4-flash，需要更强推理时切 deepseek-v4-pro。 DeepSeekApi.java:238

    你会看到 401 Unauthorized（启动成功，请求失败）

    因为key 格式对但无效、欠费，或 base-url 指向了一个需要不同鉴权的网关。 改成先用 curl 直接打一次 https://api.deepseek.com/chat/completions， 确认 key 本身可用，再回来怀疑代码。

    你会看到 404 Not Found

    因为base-url 多了或少了路径，或指向了不兼容的网关。客户端会在 base-url 后面拼 /chat/completions；如果 base-url 已经包含了完整端点， 就会重复拼接。用默认地址，或先确认网关要求的完整路径再改。

    你会看到 No qualifying bean of type 'ChatModel'

    因为DeepSeek 的自动装配条件不满足：最常见是 spring.ai.model.chat 被设成了 别的值，或者 starter 根本没进来（Maven 里写了但 IDE 没刷新）。 改成先 mvn dependency:tree | findstr spring-ai 确认依赖存在，再检查那个 spring.ai.model.chat。

    两个厂商的 starter 同时在 classpath 上

    两个 ChatModel Bean 会让 ChatClient.Builder 不知道该用哪个，启动时报 「expected single matching bean but found 2」。用 spring.ai.model.chat=deepseek 显式选一个，另一家的自动装配就不会生效。

12 · MCP 服务端

上一章是把外部工具接进来，这一章反过来：把你已有的 Spring 服务暴露成 MCP 工具，让别的 Agent、IDE 或 同事的客户端直接调用。核心只有两个注解，但协议选择、端点、鉴权与暴露面需要一次想清楚。

读完你能做到

  • 用 @McpTool 把一个 Service 方法暴露成 MCP 工具，并用 Inspector 验证
  • 在 STREAMABLE / SSE / STATELESS 与 stdio 之间做出选择
  • 说清注解扫描的生效条件，以及为什么有时「工具列表是空的」
  • 给 MCP 端点加上鉴权、限流与只读约束，而不是把内部接口裸奔出去

先说为什么：一次实现，多处消费

你写的订单查询、工单创建、报表导出，本来只服务自己的前端。暴露成 MCP 之后，任何支持 MCP 的客户端 （IDE、桌面 Agent、别的团队的聊天机器人）都能发现并调用它们，而不需要你为每个客户端写一套 SDK。

你的 Spring Bean
业务逻辑、事务、权限校验都还在这里，MCP 只是多了一层协议入口。
注解 + 扫描器
启动时扫描 @McpTool / @McpResource / @McpPrompt，生成 MCP 能力清单。 McpServerAnnotationScannerProperties.java:27
传输层
WebMvc / WebFlux 暴露 HTTP 端点，或 stdio 作为子进程被客户端拉起。

四种运行方式：先选协议

方式 开启方式 适合
Streamable HTTP（默认） spring-ai-starter-mcp-server-webmvc 或 -webflux，protocol=STREAMABLE 对外提供 HTTP 服务，新版客户端
SSE 同上，protocol=SSE 只支持旧规范的客户端
STATELESS protocol=STATELESS 无状态、易水平扩展，但不能用需要会话的能力
stdio spring-ai-starter-mcp-server + stdio=true 作为本地子进程被 IDE / 客户端拉起

协议默认值与枚举McpServerProperties.java:100； stdio 默认关闭McpServerProperties.java:65。

默认选 Streamable HTTP

它是新规范推荐的方式：普通 HTTP 语义、容易过网关、支持流式响应。只有在对接老客户端时才开 SSE； 两者不要同时暴露给同一批用户，否则排障时很难判断问题出在哪条链路。

最小可跑：把订单查询暴露出去

    <dependency>
      <groupId>org.springframework.ai</groupId>
      <artifactId>spring-ai-starter-mcp-server-webmvc</artifactId>
    </dependency>
package com.example.demo;

import org.springframework.ai.mcp.annotation.McpTool;
import org.springframework.ai.mcp.annotation.McpToolParam;
import org.springframework.stereotype.Service;

@Service
class OrderMcpTools {

    private final OrderRepository orders;

    OrderMcpTools(OrderRepository orders) {
        this.orders = orders;
    }

    @McpTool(description = "按订单号查询订单状态与金额，只读")
    OrderView query(
            @McpToolParam(description = "订单号，例如 SO-20261106-001") String orderNo) {
        return this.orders.findViewByOrderNo(orderNo);
    }
}
spring:
  ai:
    mcp:
      server:
        name: order-mcp
        version: 1.0.0
        instructions: "订单查询服务，只提供只读查询"
        protocol: STREAMABLE
        streamable-http:
          mcp-endpoint: /mcp

启动后 MCP 端点是 POST http://localhost:8080/mcp。用官方 Inspector 验证： 

npx @modelcontextprotocol/inspector
# Transport 选 Streamable HTTP，URL 填 http://localhost:8080/mcp
# 连接后能看到 tools/list 里有 query

三类能力：Tool / Resource / Prompt

注解 是什么 客户端怎么用
@McpTool 可执行的函数，有参数 schema 模型决定调用，等价于本地 @Tool
@McpResource 可读取的数据（文件、配置、记录） 客户端按 URI 读取，不经过模型决策
@McpPrompt 预置的提示词模板 客户端选择模板并填参数 
@McpResource(uri = "order://policy/refund", name = "退款政策")
String refundPolicy() {
    return Files.readString(Path.of("docs/refund-policy.md"));
}

@McpPrompt(name = "order-summary", description = "生成订单摘要")
String orderSummary(@McpToolParam(description = "订单号") String orderNo) {
    return "请总结订单 " + orderNo + " 的状态、金额与风险点。";
}
Tool 与 Resource 的分工

Tool 会被模型「自主决定」调用，参数由模型填，风险更高；Resource 是客户端主动读取的固定内容， 更像「把文档挂出去」。能用 Resource 表达的内容，不要做成 Tool。

@McpTool 还支持给客户端看的提示：readOnlyHint、destructiveHint、 idempotentHint。它们只是提示，不是强制约束，真正的权限仍要在服务端校验。

注解扫描：为什么工具列表是空的

扫描器默认开启（spring.ai.mcp.server.annotation-scanner.enabled=true），但它只扫描 Spring 容器里的 Bean。以下情况会导致「连上了，但一个工具都没有」：

  • 方法所在的类没有 @Component / @Service，没进容器；
  • 用了 new 创建对象，而不是注入；
  • 只引了 spring-ai-starter-mcp-server（stdio 版），却用 HTTP 客户端去连；
  • 方法不是 public，或参数类型无法生成 schema。

扫描开关McpServerAnnotationScannerProperties.java:29。

服务端配置一览

配置项 默认值 说明
spring.ai.mcp.server.enabled true 总开关
...server.name / version mcp-server / 1.0.0 服务标识，客户端会展示
...server.instructions 无 告诉客户端「这个服务是干什么的」
...server.protocol STREAMABLE SSE / STREAMABLE / STATELESS
...server.stdio false 是否启用标准输入输出传输
...server.expose-mcp-client-tools false 是否把下游 MCP 工具再暴露出去（慎用）
...server.request-timeout 20s 等待处理结果的超时
...server.streamable-http.mcp-endpoint /mcp Streamable HTTP 路径
...server.streamable-http.keep-alive-interval 不设置 长连接保活间隔

前缀与默认值McpServerProperties.java:50； expose-mcp-client-tools 默认关闭McpServerProperties.java:106。

鉴权与限流：别把内部接口裸奔出去

MCP 端点和普通 HTTP 接口没有本质区别，Spring Security 的过滤器链对它同样生效。最小做法： 

@Bean
SecurityFilterChain mcpSecurity(HttpSecurity http) throws Exception {
    http
        .securityMatcher("/mcp/**")
        .authorizeHttpRequests(auth -> auth.anyRequest().hasRole("MCP_CLIENT"))
        .oauth2ResourceServer(oauth2 -> oauth2.jwt(Customizer.withDefaults()))
        .csrf(csrf -> csrf.disable());   // MCP 客户端通常不带 CSRF token
    return http.build();
}
三件必须做的事

① 鉴权：谁能连；② 授权：哪个客户端能调哪些工具（按角色或工具名过滤）； ③ 限流与审计：每次工具调用记录调用方、参数摘要、耗时、结果状态，防止被当成免费算力或 数据导出通道。

还要限制暴露面：只把确有必要的方法加 @McpTool；写操作单独做幂等键； 返回结果做分页与字段裁剪，别把整个实体图丢回去——它最终会进入某个模型的上下文。

陷阱与窍门

Inspector 连上了，但工具列表为空

因为方法所在的类不是 Bean，或引错 starter。改成确认类上有 @Service、方法 public 且参数能生成 schema；HTTP 场景必须用 -webmvc / -webflux 的 starter。

stdio 模式客户端解析失败

因为应用把日志打到了 stdout，和协议帧混在一起。改成日志输出到 stderr， 或使用文件日志；stdout 只留给 MCP 协议。

浏览器/客户端访问 /mcp 返回 401 或跳登录页

因为Spring Security 默认拦截了所有路径。改成为 /mcp/** 配置明确的认证方式，并关闭对无状态客户端不友好的 CSRF。

老客户端连不上

因为默认协议是 Streamable HTTP，老客户端只会 SSE。改成临时设 protocol=SSE，并规划客户端升级。

打开了 expose-mcp-client-tools 后出现奇怪的递归调用

因为本服务既当客户端又当服务端，把下游工具再暴露，形成环。改成保持默认 false，需要透传时显式设计白名单。
